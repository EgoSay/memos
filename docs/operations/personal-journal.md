# Kairos：日常运行与数据保障

本实现承接 PRD v0.2。用户在创建 18 条开发议题后明确授权按 issue 迭代开发；旧设计文档中的“仅需求阶段”是历史基线，不是当前实施状态。原设计文件保持冻结；工程验证见 [验收记录](personal-journal-validation.md)。

## 日常使用

首页只提供记录与活动日历。文字、照片或音频可以单独保存；不必填写标题、标签或分区。记录日期可改，来源和实际录入时间另存。编辑器显示本机草稿、待同步和远端已保存的不同状态。默认私密。

“随便看看”包含每日回顾、随机漫步、AI 洞察，以及分享、分区、最近删除和数据入口。回顾每天最多三条；漫步保留本次前后阅读历史；均不产生任务、连续天数、红点或提醒。

AI 必须配置服务、手选记录并点击开始。仅发送所选正文和日期；不自动转写或扫描全部内容。未主动保存的结果不写入档案。真实模型输出质量还需使用本人选择的服务检查。

分享默认固定快照，必须预览实际范围。链接可设置提取码、期限、暂停及轮换。固定分享不会自动跟随正文编辑；删除或归档会撤销对应条目。动态分享显式选择，新增导入内容不会自动进入之前授权的动态范围。链接持有者授权不能代替指定身份控制。

分区是个人组织，不是 Memos 的协作 Space。仅显式启用目标的分区自动投递完整的新记录；普通编辑器不会沿用上一次外发分区。保存按钮显示外发目标，历史内容默认不补发。接收回执与平台发布回执分开显示。删除分区保留原记录。

## 启动与构建

需要 Go 1.27.0、Node 24 与项目指定的 pnpm 11。构建时依次运行：

```sh
cd web
pnpm install --frozen-lockfile
pnpm release
cd ..
go build -buildvcs=true -o kairos ./cmd/memos
./kairos --addr 127.0.0.1 --port 5230 --data /absolute/private-data
```

启动不传 `--instance-url`，新私有实例保持私密访问模式；首次进入由本人建立管理员账户。部署公网、HTTPS、域名和账户密钥需要对应部署环境，不应将本机端口测试等同于上线。旧实例升级前先停止写入并备份；26.10 迁移为三个数据库新增 journal_document，不自动改动旧公开记录。

## 本机草稿与离线

浏览器 IndexedDB 保存正文、文件 Blob、待同步请求和稳定记录 ID。实际本机落盘后才显示草稿状态。编辑冲突保留服务器版本和本机修改，继续处理后再提交完整记录校验值。正文、日期、位置、附件集合等都参与并发校验。

离线冷启动需要至少成功联网打开一次本产品。Service Worker 仅缓存静态应用壳和构建资源；不缓存私密 API、原件、集合访客页或分享令牌页面。网络显示在线但服务器不可达时，同样允许已在此设备登录过的账户写本机草稿；该本机身份标记不能访问服务器。退出登录清除该标记。

浏览器清理网站数据、存储额度不足、设备损坏会影响本机数据。系统杀进程、真实手机录音与键盘仍需在本人主用设备上验证；桌面仿真视口不代表真实设备已通过。

## 个人可迁移档案

“数据与备份”下载 ZIP，可解压阅读 Markdown、媒体及元数据；可选择最近 30 天编辑历史。默认不含草稿与最近删除。原件缺失、外链依赖明确列在报告中。分享和同步规则保留脱敏历史，不含可用链接令牌、Webhook 地址/密钥或存储密钥。

恢复先上传并检查文件，再显示数量、原件与 SHA-256；用户确认后恢复。上传上限 1 GiB，解压上限 2 GiB，单文件 256 MiB，最多 30,000 文件。拒绝路径穿越、重复条目、符号链接和校验不一致。UID 冲突会创建独立私密副本，不覆盖原记录。同一档案重试沿用恢复映射。

恢复会暂停本账户已有分享与同步；分享令牌重新生成且暂停、同步地址和凭证需重新配置、旧投递不重放。已发布映射及事件标识保留供核对。其他账户的配置不受影响。

## 整实例 SQLite 备份

个人档案不包含账户及全部数据库状态，不能代替实例备份。`scripts/journal_backup.py` 为 SQLite 提供停机一致性备份与隔离恢复；MySQL/PostgreSQL 请使用各数据库一致性快照配合媒体备份。S3 与外链会列为外部依赖，脚本不会冒称已经备份远端对象。

先停止对应实例，再将输出放在数据目录之外：

```sh
python3 scripts/journal_backup.py backup \
  --source /absolute/private-data \
  --database memos_prod.db \
  --output /independent-disk/journal-2026-10-03.zip \
  --server-stopped
python3 scripts/journal_backup.py restore \
  --archive /independent-disk/journal-2026-10-03.zip \
  --destination /absolute/new-restored-data
```

恢复拒绝覆盖现有目录。逐文件检查哈希、数据库完整性和核心条数，输出 restore-report.json；原始媒体保持原字节。恢复副本撤销旧登录和访问令牌、暂停分享及外发、清除外发与 AI 凭证，不重放历史任务。整实例 ZIP 包含账户数据和原数据库秘密，必须按私密备份保管，不能作为普通内容分享。

上述 ZIP 是可选的人工恢复工具，不能与生产自动备份混淆。2026-10-08 已另行部署服务器每 5 分钟的在线一致性快照及 restic 加密 R2 增量备份，Mac 每小时下载校验后保留独立加密仓库，Worker 每 5 分钟检查状态；真实定时回执、远端全量读取及独立恢复均已验证。详见 [部署与恢复工具](../../scripts/README.md) 和 [验证记录](personal-journal-validation.md)。Mac 需本人登录、开机联网；服务器备份不依赖它在线。尚未上传的浏览器草稿不在服务器备份中。恢复密钥需本人另存密码管理器或离线介质。
