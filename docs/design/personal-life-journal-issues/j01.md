# 需求评审与低保真交互原型

> 状态：需求已整理，待评审/实施；创建 issue 不代表具体默认值已全部通过，也不代表编码或真实外发已获批准。

产品总需求：[#1：完整 PRD](https://github.com/EgoSay/memos/issues/1)。对应本地 PRD v0.2；所有建议默认值服从总需求 R01–R09 的评审结果。

## 背景与目标

功能齐全不等于长期愿意使用。需要先验证记录是否直接、探索是否自愿，以及分享和外发是否可理解，再决定实现。

## 产品与交互边界

这是本人长期、真实、轻松记录生活的工具。普通记录默认私密，探索主动进入；允许本人配置范围分享与分区自动同步，保留日历数量着色。不添加连续任务、强制整理、成长评价或社交运营目标。

## 功能需求

- 把 PRD 的 C01–C10 作为已确认方向；R01–R09 的具体默认值逐项记录决议，不把建 issue 当成全部默认设计通过。
- 评审通过后产出手机与桌面低保真原型：记录、详情、搜索、随便看看、每日回顾、随机漫步、AI 选择及结果、分享和访客页、分区同步、数据设置。
- 走通八段故事：随手保存、久别打开、主动回顾、随机翻阅、手选 AI 后离开、范围分享、分区自动同步、日历日期跳转。
- 同时展示断网、附件失败、来源删除、撤销分享、同步失败等状态；只用明确标记的虚构数据。

## UI 与交互规范

- 默认进入记录；探索入口稳定可见，无红点、推送、强制引导或完成指标。
- 手机首次进入不弹键盘，输入始终易达；桌面和手机保持一致术语与返回语义。
- 低保真阶段不联调真实 AI、外部发布或私人数据。

## 验收条件

- [ ] R01–R09 有明确通过、修改或未决状态，未决项能定位到受影响任务。
- [ ] 八段核心故事及关键失败路径可在原型中演示。
- [ ] 保存后无需分类、反思或进入其他功能；几个月不来仍无负担。
- [ ] 主用设备、AI 服务、备份目的地和首个社媒目标分别登记；缺项只阻塞相关技术设计。

关联总需求验收：AC03、AC04、AC22。这些是未来验收条件，当前没有勾选为完成。
