# Webhook 持久投递、去重、顺序与授权复核

> 状态：需求已整理，待评审/实施；创建 issue 不代表具体默认值已全部通过，也不代表编码或真实外发已获批准。

产品总需求：[#1：完整 PRD](https://github.com/EgoSay/memos/issues/1)。对应本地 PRD v0.2；所有建议默认值服从总需求 R01–R09 的评审结果。

## 背景与目标

现有有界内存队列可能丢弃任务。真实同步需要重启可恢复、重复可识别，并防止撤销授权后继续发送旧正文。

## 产品与交互边界

这是本人长期、真实、轻松记录生活的工具。普通记录默认私密，探索主动进入；允许本人配置范围分享与分区自动同步，保留日历数量着色。不添加连续任务、强制整理、成长评价或社交运营目标。

## 功能需求

- 持久化事件与目标状态，事件关联稳定 ID、记录、版本及目标；签名、有限重试和失败恢复可追踪。
- 每次投递/重试复核当前分区、授权、删除和版本；旧版本不能覆盖新版本，暂停后不得继续排队正文。
- 多目标独立投递，成功目标不因另一个失败而重复创建；与接收端约定幂等键及外部记录映射。
- 更新与撤回能力逐目标确认；撤回仅发送最少标识，不带已删除正文。
- 恢复备份或导入不重放历史事件，外部映射可核查；密钥与敏感正文不进入普通日志。
- Webhook 接收确认与发布回执分开；接收方缺乏幂等时不承诺端到端恰好一次。

## UI 与交互规范

- 错误信息能定位目标和恢复动作，失败不阻止继续记录。
- 用户能看到哪些已送达、哪些结果未知；不靠含糊的同步成功。

## 验收条件

- [ ] 进程重启、超时、重复和乱序模拟下任务不无声丢失，旧版本不倒灌。
- [ ] 一个目标成功另一个失败，重试不会重建成功目标帖子。
- [ ] 授权撤销及删除后，排队和重试均不能继续发送原文。
- [ ] 备份恢复后无自动外发；只有可验证平台回执显示已发布。

关联总需求验收：AC30、AC31、AC32、AC36。这些是未来验收条件，当前没有勾选为完成。
