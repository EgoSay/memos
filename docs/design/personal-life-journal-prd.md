## 1. 本次评审的对象

本工具为 Evan 自己记录生活和自己而存在。不考虑收费、增长、其他用户画像或商业验证。长期价值是：想记的时候容易留下，偶尔想看时容易翻开，隔很多年仍能找到并带走自己的记录。

记录默认私密；本人可主动选定范围对外分享，也可为指定个人分区配置自动同步。保留活动日历的记录数量着色，以本人认可的轻微激励支持记录习惯。自主性体现为本人决定开放范围、自动化规则和界面反馈的强度。

v0.2 修订：取代 v0.1 中“首版无分享入口”“不保留数量着色”的提案，明确保留个人分区和分区 Webhook。多人共写、公开内容社区仍不纳入；本轮仅修订文档，未创建真实分享链接或启用外发。

本次提交产品哲学、功能范围、页面结构、交互规则、异常恢复和验收场景。它们是可评审的要求，不是已实现能力。评审通过后，建议只进入低保真页面与交互原型阶段；编码、数据库变更、部署和真实私人数据导入不由本次评审自动授权。

## 2. 产品哲学与取舍顺序

### 2.1 记录本身已经完整

保存一条内容即完成这次使用。产品不在保存后索取标签、总结、心情评分、关联记录或下一条输入。记录可以没有标题、没有主题、没有结论，也可以只有一张照片或一段声音。

### 2.2 允许间断

几个月没有打开不构成失败。再次进入时呈现熟悉的界面，不出现断签、补记任务、未完成回顾、回归问候弹窗或积压提醒。日历可通过数量着色呈现积累，让本人自然受到鼓励；空白日期保持中性，不表现未达标或欠下任务。

### 2.3 内容由本人解释

真实不是系统评分。产品不检验用户是否坦诚、不要求表达积极、不判断人生是否进步。本人可以修改和删除；系统提供误操作恢复能力，不建立不可更改的人生档案。

### 2.4 发现的主动权在本人

回顾、漫步、洞察始终是可进入也可忽略的去处。不用它们，记录工具仍完整可用。惊喜来自真实旧内容在新时刻被阅读；不靠红点、通知、自动播放、惊叹文案或算法制造紧迫感。

### 2.5 AI 提供一种阅读角度

AI 只在本人明确触发的范围内处理材料，不自动改写原记录、不创建默认人格画像、不把推测变成人生结论。用户不认同或直接关闭结果，不产生任何补充任务。

### 2.6 界面简单，保存可靠

备份、恢复、同步、媒体完整性和可迁移性是必要能力，但无需占据日常主界面。必要的保存失败或容量错误必须可见；“安静”不意味着隐藏失败。

本人授权的对外分享与分区自动化，也遵循可见、可停、可追溯的原则。配置好同步分区以后，符合规则的内容可以自动发送；普通记录不需要反复回答是否分享。数量着色是已认可的界面反馈，不因此增加连续记录排名或目标。

### 2.7 冲突时的取舍顺序

数据不丢失及隐私边界 → 本人控制权 → 记录的低负担 → 阅读与找回 → 偶然探索的乐趣 → 装饰与扩展。

例如：为可靠地保留草稿而显示一行保存状态是必要反馈；为提高回顾点击率而显示红点违反本原则。分享、关联和 AI 功能不能增加每次保存的必经步骤。

## 3. 产品范围与完成含义

### 3.1 首个完整版本应覆盖

| 能力 | 范围 | 作用 |
| --- | --- | --- |
| 日常记录 | 文字、照片、录音；可编辑、删除和恢复 | 轻松留下本人表达 |
| 基础找回 | 时间线、日期定位、关键词搜索；标签自愿使用 | 想找时能找回 |
| 活动日历 | 按日记录数量着色、点击定位、可隐藏 | 展示积累，提供本人认可的轻微激励 |
| 每日回顾 | 本人进入后看到少量旧记录 | 不必先记起某个关键词 |
| 随机漫步 | 一次一条，随机翻阅、可后退 | 偶然发现旧片段 |
| AI 洞察 | 从选定记录生成可回溯的阅读角度 | 满足偶尔的好奇 |
| 数据保障 | 草稿保护、清晰保存状态、备份、导出、恢复验证 | 支撑长期使用 |
| 自定义分享 | 时期、标签、自选记录；有范围的只读链接 | 由本人决定别人可以看见哪一部分 |
| 个人分区与外部同步 | 分区整理、按分区启用 Webhook、投递状态与停止 | 指定内容按本人设置流向其他平台 |
| 私人边界 | 本人登录、私密默认；分享、分区和同步授权分离 | 普通记录不会因其他外发操作被一并公开 |

“首个完整版本”包含三个探索功能以及 v0.2 的自定义分享、个人分区、活动日历与分区 Webhook。可以分批实现；若只完成 Webhook 投递，尚未验证社媒发布链路，必须明确说明尚未完成实际社媒同步。首个具体社媒平台与接收服务待 Evan 选定，不默认承诺支持所有平台。

### 3.2 暂不纳入

公共社区、关注点赞、多人协作、家庭共写、会员收费、增长分析、连续记录奖励、情绪打分、主动写作问题、定时回顾通知、自动周报年报、知识图谱、人生章节管理、数字分身、自动全文画像、书籍打印、视频剪辑、原生多平台同时开发。

保护实际已有的个人内容、媒体和必要关系；不因 UI 简化就删除资料，也不为兼容而永久保留所有上游模块。个人分区、分享与 Webhook 明确保留并改造；成员邀请、公开内容发现和社交互动不进入本人日常界面。后续分别核查数据迁移、实际权限和代码复用。

### 3.3 如何判断产品做对了

由 Evan 的实际体验和下面的可验证行为判断：可以不分类地保存；不探索也不受打扰；间断后无负担地继续；探索可以随时退出；原文保持可辨认；离开工具后仍能读取档案。

不使用日活、停留时长、连续天数、回顾完成率、洞察生成数量来证明产品成功。不为验收默认采集私密正文或安装行为分析服务。个人长期愿意使用，需要真实时间检验，原型通过不能证明这一点。

## 4. 页面结构与发现方式

以下路径为信息架构示意，不是本次批准的路由改动。

| 页面 / 示意路径 | 首要内容 | 主动作 | 次要动作与返回 |
| --- | --- | --- | --- |
| 记录 `/` | 简洁输入区、个人时间线、活动日历 | 写下并保存 | 搜索、分区筛选、日期定位、选内容分享 |
| 随便看看 `/revisit` | 每日回顾、随机漫步、AI 洞察三个稳定入口 | 自己选择一种看法 | 返回记录；不自动生成或显示私密回忆 |
| 每日回顾 `/revisit/daily` | 少量旧记录、原始日期、原文与媒体 | 阅读 / 打开原记录 | 返回；更多操作中可设为不参与随机回看 |
| 随机漫步 `/revisit/wander` | 当前一条旧记录 | 换一条 | 上一条、打开原记录、退出 |
| AI 洞察 `/revisit/insight` | 来源选择、发送范围、生成结果 | 选择记录后开始 | 取消、查看来源、明确选择保存 |
| 记录详情 `/memos/:uid` | 原文、记录日期、媒体 | 阅读 | 编辑、引用、分享、分区与删除；返回原位置 |
| 搜索 / 日期定位 | 查询条件与结果 | 找到记录 | 清除条件、返回原滚动位置 |
| 分享创建与管理 `/shares` | 选定内容、访问方式、固定/动态模式、访客预览 | 创建或更新分享链接 | 停用、移除条目；管理页不自动发送链接 |
| 对外阅读 `/s/:token` | 本链接获准呈现的记录和媒体 | 只读浏览 | 无私人导航、全库搜索或其他记录数量 |
| 分区 `/partitions/:id` | 本分区记录、当前同步目标和状态 | 记录 / 移入内容 | 配置同步、暂停、查看失败 |
| 设置 `/settings` | 私密访问、显示、AI、数据、分享与同步管理 | 按需维护 | 不承担日常记录入口 |

手机建议使用“记录 / 随便看看”两个带文字的主入口，设置位于低强调菜单。桌面以窄侧栏承接相同结构。三个探索入口不埋在设置中，也不放到每条新记录旁边争夺注意力。首次进入不会强制介绍全部功能。

活动日历在桌面记录页侧栏默认可见，手机放在输入区之后的紧凑月历区域并可折叠，不挤占输入首屏。分区选择属于记录页内的可选筛选与归属操作，不新增多人协作流程。分享从当前筛选结果或手选记录发起；同步目标和最近状态只在对应分区及管理入口突出展示。

默认打开“记录”；浏览器返回和同次会话内返回保留所在页面、筛选条件和滚动位置。移动端首次打开不自动弹键盘，点输入区后进入编辑；桌面输入区可以获得焦点，但不能抢走正在操作的搜索或对话框焦点。

“随便看看”是建议的工作文案；最终名称可在低保真评审中调整，不涉及改名或品牌实施。

## 5. 日常记录需求

### REC-01 低门槛输入

输入区使用中性占位文案“记点什么……”。可直接输入并保存；标题、标签、心情、位置均非必填。无正文但有有效照片或录音可以保存。完全空白时保存按钮不可用，不弹出训诫式提示。

初始工具只露出照片、录音和保存；格式化、标签和日期调整在次级位置。保留长文能力，但不让排版工具主导首屏。文字按本人输入保存，不自动润色、加标题或总结。

在默认记录页新建时不继承上一次使用过的外发分区；已有草稿则保留其明确归属。在具体分区内主动新建可以继承该分区，但编辑器必须显示归属。若分区已开启自动同步，保存前就显示目标及“保存并同步”动作；不把外发事实藏在更多菜单，也不为每条重复弹出确认。

### REC-02 草稿与正式保存

自动保留草稿；点击“保存”才形成正式记录。草稿不进入回顾、漫步、AI 来源池或正式记录列表。返回草稿是恢复输入，不弹“你还有未完成任务”。明确“放弃草稿”可清除它。

状态必须有独立语义：

- “草稿已保存在此设备”：本地持久化已成功，不代表服务器收到。
- “已保存在此设备，待同步”：本人已保存为记录，本地写入成功，远端确认尚未完成。
- “正在同步”：正在发送或确认，不能提前显示完成。
- “已同步”：正文及本条应有的附件均已确认成功。
- “附件待重试”：正文可已同步，但记录尚不完整。
- “未能保存”：本地持久化也失败；保留当前输入并提供重试或复制等恢复动作。

保存成功使用就近、短暂的文字状态；不播放音效、不庆祝、不推荐下一步。重复点击或请求超时重试不能创建重复记录。键盘快捷键建议桌面 Cmd/Ctrl+Enter 保存，普通 Enter 换行，中文输入法组合输入不触发保存。

### REC-03 照片与声音

照片选择后先出现稳定的本地预览和上传状态；录音由本人点击开始，展示录制中、时长、停止和取消。仅在触发时申请对应权限，拒绝后仍能写文字。音频和视频不自动播放。

录音停止后可试听、保存或删除。转写是独立的主动操作，失败不删除原音、不阻止保存。转写显示为可检查的候选文字，由本人决定是否加入正文；技术上的来源信息不能因加入正文而丢失。

新上传的私有照片及录音应保留原文件；缩略图或兼容格式另存为衍生版本。既有文件可能已经被 Memos 处理过，不得承诺恢复从未保存的原始字节。媒体原件保存与磁盘容量需在实施前验证。

### REC-04 时间与修改

默认记录日期为当前本地日期时间，可自愿调整以补记过去。系统分别保留本人指定的记录日期、实际录入时间、修改时间和必要时区信息；页面通常只显示一个自然的记录日期，其他信息按需展开。

导入记录的原始写作时间无法确认时标为未知，不把导入时间伪装成当年的写作时间。日期不精确时不补造事实；模糊日期的高级表达不纳入首版。

编辑是普通动作，不要求填写修改原因。旧版本在次级恢复入口提供，不在正文上反复突出“你修改过”。建议首版保留最近 30 天的可恢复版本；这是误操作保护的提案，不是永久存证承诺。

### REC-05 删除与恢复

建议删除先进入“最近删除”，保留 30 天；提供撤销和恢复入口。彻底删除需要明确确认。普通返回、放弃探索或关闭洞察不出现这种确认。

已删除内容立即退出搜索、回顾、漫步和 AI 来源池。进入删除流程的原记录，其洞察缓存和已保存衍生结果同步失效或移除相应内容；不允许已删原文仍从洞察中显露。独立备份存在保留周期，实际清除边界在数据设置说明，不承诺一键消除用户已下载的副本。

本应用管理的分享内容和媒体授权也立即撤销对应条目，恢复原记录不会自动恢复此前分享授权。已经同步到社媒的副本按外部平台撤回策略单独处理，不能把本地删除提示成所有平台都已删除。

### REC-06 找回

记录列表按日期浏览；活动日历保留按每日记录数量着色和日期跳转，具体计数与反馈规则见 CAL-01–CAL-03。搜索首版支持关键词和日期范围，标签为可选辅助；日期、标签筛选结果可以作为分享选取的起点。

音频通过已有且本人认可的文字转写检索；没有转写时只支持日期等已有信息，不宣称理解音频内容。离线搜索若仅覆盖本机缓存，应清楚说明范围，不能把未缓存内容视为不存在。

## 6. 每日回顾需求

### REV-01 触发与内容

只在本人进入“每日回顾”时展示。打开应用、保存记录、进入“随便看看”均不自动展开回忆，不触发通知、后台 AI 或完成任务。

建议每个本地自然日最多呈现三条，数量是减轻阅读负担的默认值。不是阅读指标；没有“已读 1/3”、勾选、完成按钮或补看历史日期的任务队列。

### REV-02 选择规则

候选范围为本人已保存、已同步、未删除、未归档、未排除且记录日期早于今天的记录。默认包含本人录入的文字、照片、声音及主动导入的历史记录；不包含草稿、其他人的内容、旧协作评论和单独保存的 AI 输出。

建议优先选一条往年同日记录，其余从不同时间随机补齐；没有往年同日记录时全部随机。候选不足三条就展示实际数量，不重复凑数。没有候选时显示“这里暂时没有过去的记录”，保留返回入口，不催促新增。

同一本地日期反复进入保持同一组，避免刷新一次就形成抽取刺激。首版建议同日选集跨设备一致；浏览期间跨越午夜或时区变更不突然替换正在看的内容，下次进入再按当前日刷新。

删除和排除即时生效，可减少当日条数，不为凑数替换成新的刺激。内容修改后回顾显示最新可读版本。候选选择不做情绪、价值或重要性排序。

### REV-03 阅读行为

显示原日期、原文和可手动播放的原媒体，不先生成总结。长文自然截断并提供“展开全文”；回到列表后保留位置。可以打开原记录编辑，也可自愿引用后写一条新记录，但不主动询问感受。

在记录更多菜单提供“暂不在回顾与漫步中出现”，用于避开不想偶然遇见的内容。记录仍留在自己的档案和主动搜索中，可在设置恢复。该设置不自动改变用户后来明确选择的 AI 分析范围。

## 7. 随机漫步需求

### WAN-01 进入与节奏

点击“随机漫步”即呈现一条候选旧记录；候选池遵循 REV-02 的归属、生命周期、日期和排除规则。一次只突出一条，保留“上一条 / 换一条”，不自动滚动、计时切换或预播声音。

### WAN-02 随机规则

首版采用纯随机，在同次漫步中尽量不重复；候选耗尽时显示中性文案“这些记录已经翻过了”，可主动“重新随便看看”或返回，不显示完成奖励。

后退回到本次见过的上一条，不重新抽取。打开详情再返回保留当前条、长文展开状态及漫步历史。关闭会话后的长期漫步历史不作为首版独立功能。

只有一条候选时可直接阅读，不要求继续；没有候选时静态说明即可。删除当前条后显示已移除状态，用户自己选择下一条，避免突然跳动。

### WAN-03 关联边界

不自动解释两条记录之间的联系，不叠加知识网络和关联推荐。用户在单条记录更多菜单主动选择“用 AI 看看这条”时，转到洞察的来源确认状态；单纯翻阅不调用模型。

## 8. AI 洞察需求

### AI-01 主动发起与输入范围

AI 洞察作为稳定入口保留。进入时显示简洁说明“选几条记录，换个角度看看”和“选择记录”，尚未调用模型。

来源选择复用关键词和日期筛选，可选一条或多条。入口来自单条记录时只预选该条；全局入口不默认选中全部历史。不自动加入相关记录、用户画像或其他会话内容。无选择时“开始看看”不可用，显示原因即可。

选择器仅提供本人可读的已保存记录，不提供草稿、已删除内容或其他人的记录。发送前重新确认来源仍存在且可访问；选择后发生删除或权限变化时停止该次发送并提示重新选择，不用旧缓存补齐。对已归档或已排除回顾的个人记录，只有主动找到并明确选中时才可分析。

开始前清楚显示所选条数、来源列表、将使用的模型服务及发送内容类型。首版建议仅发送所选记录的正文和必要日期；照片、原音、精确位置及其他元数据不隐式发送。纯媒体且无可用文字时说明当前支持范围，不自动转写或识图。

语音转写和洞察的服务设置可以复用入口，但授权含义分开。首次配置云端服务时说明内容将发送到该服务；每次来源变化都要可见。后续不用重复冗长弹窗，但用户的“开始”仍是每次发送的触发点。

### AI-02 输出约定

默认提供一个短的观察角度，可附一至三个来源引用；不铺满多维人格报告。记录不足时可以返回“这几条记录暂时不足以形成清楚的观察”，不编造联系。

观察中的事实必须能回到所选原文。区分“记录中写到”与“也许可以这样理解”，避免“你本质上”“你一直”“这证明”等超出证据的定性。无需强行积极、成长或疗愈叙事，不诊断心理状况。

原文和洞察采用分开的视觉容器，标注“AI 洞察”，不以本人语气自动写入正文。生成内容不携带执行修改、分享、删除或调用外部动作的能力；记录中的命令式文字仅作为材料阅读。

### AI-03 结果的去留

阅读后可以直接返回，不要求评价、采纳、写感受或继续对话。默认结果仅在当前会话供查看，不自动写进生活时间线或形成永久洞察历史。

提供次级动作“保存这次洞察”。主动保存后作为有来源的独立 AI 内容保留，默认不进入每日回顾和随机漫步，也不默认成为后续 AI 的输入材料。已保存洞察可从洞察页次级历史入口找到，支持删除及导出。

如本人想写自己的感受，可打开普通编辑器；不自动复制 AI 文本、不强制引用。如果主动复制了 AI 内容，应保留可辨认的来源，不将系统生成物静默伪装为旧时本人原话。

### AI-04 失败、取消与失效

生成时允许取消；离开页面应取消继续交付结果，不因此阻塞记录。请求已发送的部分可能无法从模型服务撤回，界面不把“取消生成”描述为远端数据撤回。

超时、无服务配置、模型不可用、来源过长等情况只影响洞察。来源过长时让用户缩小范围，不静默截断并声称读完。结果引用缺失或引用了未选材料时不当作可信成功交付。

原记录修改后，已有洞察标记“来源已更新”，不静默展示成对最新文字的判断；用户可主动重新生成。原记录删除后按 REC-05 移除可泄露被删内容的衍生结果。历史来源维护不应产生通知或待办。

## 9. 自定义分享需求

### SHR-01 分享范围

本人可以从时间线、搜索结果、标签或记录详情发起“分享这些记录”。支持三种基本选法：某段日期范围、某个标签、手动选择若干条。日期与标签可以组合，组合时取交集；结果可继续手动排除。

日期依据本人设定的记录日期，起止日按创建分享时显示的时区解释并固定边界。标签默认精确匹配，是否包含子标签需要明确选择；多个标签使用“任一 / 同时满足”的可读描述，不让用户猜筛选语义。手选结果不因为后台分页、排序或筛选变化而丢失选择。

默认只提供本人已保存、已同步、未归档、未删除的原始记录。AI 洞察和其他衍生内容不自动混入；未来分享它们需要单独显式选择并保留 AI 标识。分享指定内容不改变原始记录的默认私密状态。

### SHR-02 固定分享与动态分享

创建面板提供两个清楚区分的模式：

- **固定分享（推荐默认）**：保存当前选中的条目及其对外内容快照。以后新增同标签记录、修改原文或更换标签，不自动改变这份分享。本人主动“更新分享内容”时预览差异后更新；移除分享条目、原记录删除或归档仍会立即撤销对应对外内容。
- **动态分享（主动启用）**：固定本人指定的日期、标签等规则；以后符合规则的新增记录进入范围，修改后的正文和媒体也随规则更新。离开规则的记录退出。面板明确说明“之后符合条件的内容也会显示”，并一直可查看当前对外列表及单条排除项。

手工挑选分享默认采用固定模式。动态规则编辑、扩大日期范围或更换标签时展示新增与移除条目；规则内日常新增内容按既有授权自动出现，不逐条弹确认。固定分享不提供一个模糊的“同步更新”开关把条目变化和正文变化混在一起。

原记录删除或归档后留下分享排除状态；恢复记录或解除归档不会自动恢复该条分享，需本人重新纳入。批量导入的历史记录也默认不进入已有动态分享，导入后可明确选择将其中内容纳入，避免导入动作意外扩大对外范围。

例：分享某次旅行可固定挑选十条；持续分享“读书”标签可以主动采用动态模式。二者均是提案示例，不代表已经存在相应私人记录。

### SHR-03 访问方式与生命周期

建议首版支持不可猜测的只读链接、可选提取码、可选有效期、随时停用和重新生成链接。创建时清楚显示访问方式与期限，包括选择不过期时的含义。

持链接可读属于链接持有者授权，可以被转发；提取码也不等于实名指定某个人。按邮箱或特定账号严格授权暂不纳入首版，如 Evan 希望做到“只有某几个人可看”，需单独确定身份验证方式，不能声称现有链接已具备该能力。

“生成链接”只创建访问入口并允许本人复制，不替本人发送给任何人。停用或到期后，后续页面、数据和媒体请求必须拒绝访问；已经被他人阅读、下载或截图的副本不承诺收回。

### SHR-04 访客预览与内容边界

流程为“选范围 → 查看别人将看到的内容 → 设置模式和访问方式 → 生成链接”。预览与访客真实页面遵循同一权限规则，展示正文、所选媒体和日期；精确位置、媒体 EXIF、内部标签、引用预览和作者其他信息默认不额外披露。原文本身写出的地址或标签仍在正文中，预览不能冒称自动脱敏。

允许分享时排除个别附件；对外媒体使用经过本分享授权的展示副本，保留私有原件。正文中未获分享的内部记录引用不展开其标题、摘要或附件；第三方内嵌内容不自动加载，避免打开页面时额外发送私密页面信息。

访客只有阅读本次分享范围的能力，无编辑、评论、全库标签列表、个人活动日历或私人搜索入口。直接修改 URL、翻页、搜索和取附件都必须受同一范围约束。页面设为不供搜索引擎收录；这不是访问控制的替代。

### SHR-05 管理与状态

本人可在管理页查看分享名称、范围摘要、固定/动态模式、期限与启用状态，打开当前访客预览，修改或停用。界面展示授权状态，不引入浏览量、点赞数等运营指标。

创建失败时保留选择与设置，不产生看似成功的链接。来源在创建过程中被删除或归档时重新校验并更新预览。空集合、错误提取码、无效或到期链接提供中性状态，不泄漏不在范围内的记录是否存在。

## 10. 个人分区与 Webhook 同步需求

### PART-01 分区的含义

分区是本人组织记录并设置外部同步规则的容器。首版建议一条记录至多归属一个分区，标签可有多个；不放入任何分区也能正常记录。“全部记录”始终是自己的完整时间线。

新分区默认私密、没有外部同步。可以有普通分区，也可以有主动启用同步的分区，例如“日常随记”和“对外片段”；名称由本人决定。创建分区不邀请成员，不授予外部访问，不自动创建分享链接。

默认记录页新内容不记忆上次的外发目标；在某分区内新建时明确显示该归属及同步状态。移动一条已有记录到启用同步的分区，是一个可见的发送意图：移动动作显示目的地和目标服务，完成后按规则处理，不再要求重复批准。

删除分区的建议行为是停止其同步规则，并将记录移回未分区，保留正文与媒体；不沿用原 Memos 删除空间时连带删除记录的行为。整理分区与删除个人生活资料必须区分。

### SYNC-01 配置与启用

每个分区可以配置一个或多个具名 Webhook 目标，设置地址、签名凭证、发送字段、事件范围和暂停状态。地址与密钥放在设置里，记录页只显示能理解的目标名称，例如“我的社媒同步服务”。

启用前说明“这个分区以后保存的新内容会发送到这些目标”，并选择是否包含历史内容。推荐默认不补发历史；需要补发时先呈现实际条目，再明确发起该批次。仅创建或修改地址不应外发真实记录；连通性测试使用明确标记的测试内容，正式启用是独立动作。

已经明确启用的规则持续有效，符合规则的新记录可自动同步，无须每条弹窗。当前任务仍是需求修订，不执行任何真实连接、测试发送或发布。

默认自动发送池为本人主动保存的原始记录；草稿、AI 洞察结果、分享快照、外部同步回执和批量导入不作为新内容自动外发。手动补发或移动记录时按明确选中的条目处理，防止系统衍生内容循环发布。

### SYNC-02 默认触发语义

| 操作 | 推荐行为 |
| --- | --- |
| 普通未分区记录 / 未启用同步的分区 | 正常保存，不发送 Webhook |
| 启用规则后的新记录保存到该分区 | 正文及应发送媒体完整可用后自动生成新内容事件 |
| 草稿编辑、录音未结束、媒体未上传完成 | 不发送半成品；显示保存或媒体状态 |
| 已有内容主动移入同步分区 | 作为该目标的新内容发送；若此前已发送同一记录则更新关联，避免重复创建 |
| 原地修改已发送内容 | 默认不自动改外部帖子；标记“本地有更新”，可手动同步更新；可在配置中主动开启自动更新 |
| 只改记录时间、标签或其他非发送字段 | 不重复创建帖子；是否同步元数据由明确的字段配置决定 |
| 移出分区、删除或归档 | 停止该条后续发送，取消尚未发送的正文任务；外部已发布内容按撤回规则另行处理 |
| 暂停规则 | 暂停所有未发出正文任务和重试；暂停期间不积累默认待发内容 |
| 恢复规则 | 默认仅处理恢复后新发生的符合条件事件；旧失败任务和暂停期内容由本人选择是否补发 |

固定分享、动态分享和 Webhook 各自拥有独立授权。生成分享链接不启动 Webhook；放入同步分区也不让浏览器匿名访问整个分区。进入其他分区本身不向外发送正文。

### SYNC-03 原始记录与平台内容

私人记录保持本人原话，Webhook 只发送配置范围内的字段。首版不自动进行 AI 改写。平台适配层可以转换排版与媒体格式，但不能默默截断正文、替换措辞或删除附件后宣称完整发布；不支持的内容类型应显示具体限制。

只发送本条获授权内容，不附带其他分区内容、私人标签清单、精确位置或内部引用目标。附件通过限定用途和有效期的授权方式交付，不把整个私人媒体库公开，也不向接收方发送本人全库访问凭证。发送媒体应使用对外展示副本，不默认携带私有 EXIF 信息。

### SYNC-04 Webhook 投递与社媒发布是两个结果

Webhook 是本工具到接收服务的投递通道。社媒最终发布还取决于接收服务、目标平台、账号授权和格式支持，具体平台尚未选定。

记录旁和分区页使用能区分阶段的状态：待发送、发送中、已送达接收服务、发布结果未知、已发布（有平台回执或帖子链接）、失败、已暂停。本地保存成功不等于 Webhook 成功；接收方返回成功也不自动证明社媒帖子已发布。

首个实际同步目标需要在后续实施阶段做端到端验证，包含文字、媒体、重复发送、更新和失败恢复。只做通用 Webhook 时如实交付为投递能力，不声称已经支持未验证的社媒平台。

### SYNC-05 可靠性、重试与停止

以持久化事件记录待发工作；事件按记录、版本和目标关联，包含稳定标识与签名，接收方据此去重。网络重试复用同一事件标识。目标不支持去重时，明确重复发布风险并采取查询/对账或人工处理，不能声称 Webhook 天然保证恰好发布一次。

发送前及重试前检查记录仍在授权分区、规则仍启用、当前待发版本仍有效；已过期的旧版本不应在新版本之后反向覆盖。移出、删除、归档或暂停后不继续发送缓存正文；已发出的请求可能无法撤回，状态应如实体现。

针对网络等暂时失败采用有上限的后台重试；权限、格式和明确拒绝类问题显示修复入口，避免无限重发。一个目标失败不让其他目标重复创建，也不阻止本地记录保存。单个分区暂停不影响其他分区。

### SYNC-06 外部更新与撤回

更新和撤回按每个目标明确配置，默认不自动删除外部帖子；如果本人启用了自动撤回，在移出、归档或删除时向已发送过的目标发送最小撤回事件，仅带目标关联标识，不再发送已撤销正文。

若平台支持，回读撤回结果；不支持或失败时标为“需要到目标平台处理”，可附已有帖子链接。撤回本工具分享链接不能删除社媒副本；暂停同步不能收回已发布内容。

部分目标更新/撤回成功而其他目标失败时分别显示状态，不用一个全局“同步完成”掩盖差异。数据导入、从备份恢复、重新配置相同分区不会自动重放历史外发事件；必须通过明确的恢复或补发动作开启。

## 11. 活动日历需求

### CAL-01 保留数量着色

活动日历默认保留按日数量着色，作为 Evan 已认可的轻微激励。沿用已有从无记录到不同数量档位的浅深层级，具体配色和分档先复用 Memos，再在原型上评估，不额外引入目标分数。

空白日期使用中性色；有记录的日期呈现积累。鼠标悬停或键盘焦点可读出日期和条数，手机可点选查看当天内容；颜色不是唯一信息通道。没有断签、排名、奖章或“今天还差一条”。

### CAL-02 数量与日期语义

建议统计本人已保存且未删除的原始记录，包含归档；一条记录无论附带多少照片、录音或标签都算一条。草稿和单独保存的 AI 洞察不计入。分享快照、Webhook 投递、平台副本以及修改、重试不产生额外条数。

按记录日期及日历设置的时区归入对应日；历史导入和补记显示在其对应日期，不把今天一次导入几百条表现成今天新写了几百条。删除或日期调整后数量同步更新；时区变化引起的边界变化须一致应用。

默认显示全部个人记录。若随分区或筛选改变统计范围，界面明确写出当前范围，不能让局部数字被误认成全库数字。访客分享页不出现本人全量活动日历。

### CAL-03 自主程度

可以在显示设置中关闭数量着色、保留普通日期定位，或隐藏活动日历。默认开启来自本轮明确偏好；不自动按使用行为调整激励强度，不进一步开启记录提醒或回顾推送。

## 12. UI 与交互体验规范

### 12.1 信息层级

主界面优先级为输入与本人内容，其次是日期和保存状态，再次是次级功能。全局设置、容量、备份详情和模型参数按需出现。探索页明确可发现，但不靠闪动、数字气泡和横幅获得注意。

每个页面只有一个显著主动作；“编辑 / 删除 / 排除回顾 / AI 看看 / 分享”收在次级菜单。危险操作与日常保存在位置及强调方式上区分。数量着色日历作为稳定的次级视觉元素保留。

普通记录只显示保存反馈；在已启用外部同步的分区，编辑器持续显示分区、目的地和“保存并同步”，后续显示分阶段结果。清楚说明外发范围所需的文字不能为了界面简洁而隐藏。分享面板展示条目数和预览属于授权范围说明，不是活动指标。

### 12.2 视觉方向

复用现有组件和排版基础，减少装饰与界面密度；具体颜色、字体、圆角在后续视觉设计阶段确定。此处不选择主题，不创建新组件库，也不变更上游品牌素材。

建议手机正文从 16px、行高 1.6–1.8 起评估；桌面阅读列约 640–760px，长段落和中文优先。主要触摸目标建议至少 44×44px。这些是原型评估起点，需要用实际设备验证，不宣称已满足任何外部标准。

日期、声音、照片保留辨认度；可弱化操作边框，不能用低对比度牺牲阅读。支持浅色与深色并尊重系统设置。缩放、长文件名、长标签、横屏、窄屏和大字体不遮挡正文或保存动作。

### 12.3 行为与反馈

| 交互 | 反馈 | 焦点 / 触摸 / 键盘约定 |
| --- | --- | --- |
| 进入输入区 | 展开必要工具，保持现有内容 | 手机主动点击才唤起键盘；无无故抢焦点 |
| 保存 | 就近展示真实保存状态 | Cmd/Ctrl+Enter；普通 Enter 换行；重复提交去重 |
| 打开探索 | 显示所选功能自身内容 | 不连带启动另外两项能力 |
| 换一条 | 稳定容器更新内容 | 按钮可键盘访问；手势可选，不能成为唯一操作方式 |
| 打开详情并返回 | 恢复原位置与上下文 | 返回焦点回到原触发元素 |
| 关闭对话框 | 保留已落盘草稿 | Escape 可关闭非危险层；不把 Escape 解释为丢弃 |
| 删除 | 撤销入口；永久删除明确确认 | 危险确认不默认聚焦确认删除按钮 |
| 录音 | 可见的录制状态与停止按钮 | 无需长按维持；权限拒绝有文字回退 |
| AI 生成 | 简洁等待状态和取消 | 加载不锁住全局导航；完成后不抢焦点 |
| 活动日历 | 按数量着色，按需展示日期与条数 | 点击跳转；键盘和触摸可访问；不依赖颜色理解 |
| 创建分享 | 先预览对外范围，再生成可复制链接 | 固定/动态与访问方式可读；生成不自动发送 |
| 保存到同步分区 | 保存前展示目标，保存后分别展示本机同步与外部投递 | 沿用已启用规则，不逐条弹审批；避免键盘快捷键绕过目标可见性 |
| 暂停外部同步 | 立即停止新任务和未发出的重试，保留历史结果 | 是普通可撤销操作；恢复不自动补发积压 |

动效只解释状态切换，建议约 120–200ms，尊重减少动态效果设置；不用翻牌奖励、纸屑、打字机式逐字情绪渲染。加载占位保持布局稳定，不能展示虚构日记。

### 12.4 文案约定

| 场景 | 建议文案 | 避免的表达 |
| --- | --- | --- |
| 输入 | 记点什么…… | 今天最大的收获是什么？ |
| 保存 | 已同步 / 已保存在此设备，待同步 | 太棒了，又成长了一点！ |
| 回顾入口 | 每日回顾 | 今日还有 3 条未完成 |
| 漫步 | 换一条 / 上一条 | 再看一条解锁更多 |
| AI 入口 | 选几条记录，换个角度看看 | 揭示真实的你 |
| 空档 | 这个日期没有记录 | 你已经很久没记录了 |
| 错误 | 未能同步，内容仍保存在此设备 | 已保存（实际仅在内存中） |
| 分享范围 | 已选 12 条，仅分享当前版本 / 后续符合条件的内容也会显示 | 分享这些（不说明范围与变化规则） |
| 同步分区 | 保存并同步到「我的社媒服务」 | 保存（实际还会向外发出） |
| 外部投递 | 已送达接收服务，发布结果未知 | 发布成功（只有 Webhook 接收回执） |
| 活动日历 | 10 月 3 日，3 条记录 | 今天还差 2 条达标 |

通知默认不提供写作、回顾和洞察推送。数据保存失败、备份失效等必要状态在应用内清晰可见；不把“没有打扰”作为静默失败的理由。

## 13. 关键状态矩阵

| 状态 | 记录 | 回顾 / 漫步 | AI 洞察 |
| --- | --- | --- | --- |
| 首次使用 / 空 | 直接输入，导入入口可跳过 | 中性说明，没有示例人生或写作任务 | 说明需要手选材料，不自动扫描 |
| 加载 | 输入区尽可能独立可用，加载不覆盖草稿 | 保持布局，等待后再展示真实内容 | 标明处理中，可取消 |
| 成功 | 依落盘与远端确认显示不同状态 | 内容出现即可，没有完成宣告 | 展示角度和来源，不强制下一步 |
| 按钮不可用 | 无正文且无媒体；说明必要原因 | 无下一条候选不制造无限抽取 | 无来源或不可处理时说明原因 |
| 离线 | 以真实本地持久化能力保存；不足则明确失败 | 可看缓存；未缓存内容提示联网 | 不发送，保留选择；记录仍可用 |
| 权限拒绝 | 文字继续可用，媒体给恢复入口 | 不增加无关权限申请 | 未配置服务时进入设置，不阻止其他功能 |
| 部分失败 | 正文和附件分别反馈，不整体冒称同步完成 | 媒体失败保留原文及重试 | 不用假内容补齐，不改原记录 |
| 登录过期 | 保留本机草稿，重新登录后继续 | 不显示他人或越权内容 | 不擅自发送，恢复后仍需主动启动 |
| 来源变化 | 冲突保留双方，用户选择后恢复正常 | 修改显示最新内容，删除移除候选 | 修改使旧结果过时，删除清理衍生内容 |
| 本地空间不足 | 明确提示，保留当前可复制内容 | 不把缓存缺失视为数据被删 | 原始记录不受生成失败影响 |

本地保存并不等于设备损坏后可恢复；同步也不等于独立备份。实现必须分别验证，文案不得混用。

分享和外发另需覆盖以下状态：

| 状态 | 分享 | 分区外部同步 |
| --- | --- | --- |
| 空范围 / 未配置 | 保留筛选，不能生成误导性的有效内容页 | 普通保存仍可用，未启用前不发送 |
| 创建 / 发送中 | 保留预览与范围，重复点击不重复创建 | 记录保持已保存状态，展示目标级投递状态 |
| 已停用 / 已到期 / 暂停 | 后续页面、数据及媒体授权失效 | 待发及重试停止；已发出的请求结果单独追踪 |
| 来源修改或移除 | 固定快照不自动改正文；动态按规则更新；删除或归档均撤销条目 | 按启用的更新/撤回策略处理，不重发未授权正文 |
| 部分失败 | 不把缺失媒体当作完整预览或成功分享 | 每目标分别显示，成功目标不随失败目标重复创建 |
| 接收成功但无平台回执 | 不适用 | 显示已送达或发布结果未知，不能冒称已发布 |
| 恢复备份 | 分享默认暂停，确认范围与期限后再启用 | 同步默认暂停，不重放旧事件；核对已发布映射后再恢复 |

从最近删除恢复单条记录时，也不自动恢复原分享条目或触发新发布；本人可以重新加入或补发。

## 14. 保存、隐私与长期可用性

### 14.1 数据归属与来源

稳定记录标识、正文、媒体原件、记录日期、实际录入与修改时间、来源类型是基础数据。AI 洞察独立关联来源记录与其版本，不混入原始生活内容。

回顾选集和漫步会话属于可重建的浏览状态；不能因浏览状态损坏而影响记录。回顾排除偏好需要保存并可撤销。默认私密覆盖新记录和新导入内容；历史公开内容的可见性迁移需单独呈现并确认，不静默改动。

个人分区归属、分享授权及其快照/规则、分区同步配置与投递结果分开保存。移动分区不等于公开访问；链接授权不等于加入分区；从分享得到的访问能力不能被复用为全库或 Webhook 管理权限。

### 14.2 离线与多设备

产品目标为已加载的应用在断网后仍能可靠保留文字与所选媒体，恢复连接后同步、去重并显示真实状态；多设备冲突不得最后写入静默覆盖另一份表达。

当前浏览器、移动系统的本地容量、录音生命周期、应用被杀后恢复以及离线冷启动能力尚未验证。进入实现前需确定主用设备并做针对性可行性验证；不能用现有 localStorage 草稿证明完整离线能力。若目标设备无法支撑某项保障，应在上线前提交明确限制或替代方案供评审。

### 14.3 备份与恢复

独立备份必须覆盖数据库和媒体，并在干净环境做恢复检查。建议在活跃使用日保留一次独立快照、默认保留最近 30 天；具体目的地、存储额度和执行方式留给技术方案，未确认前不得宣称已受备份保护。

设置中展示最后成功备份时间和状态；失败以克制但可见的状态提示，不用持续弹窗。恢复后核对正文、日期、附件、来源和主动保存的洞察等范围，报告未恢复项目。

备份应保留分享和同步配置、事件标识及外部帖子映射，以便核查和恢复，但恢复运行时默认暂停分享及外发；不能因回滚旧数据库让已经停用的链接重新有效或让已发帖子重复发布。凭证按独立安全配置恢复，不写入普通内容导出。

### 14.4 导出与导入

导出必须提供可独立解压阅读的正文、必要元数据和所管理媒体，不要求继续运行本应用才能理解。媒体仅有外链时明确列为外部依赖，不能算已保存的文件副本。主动保存的 AI 内容单独标识；默认不含草稿、最近删除和原始密钥。

现有 Memos 导出可作为基础，但新增日期语义、来源及恢复数据需要明确兼容方案。个人内容导出与实例备份分别命名，避免以能导出笔记代替已备份设置、身份或全部历史版本。

个人内容导出可保留分区名称与非秘密来源信息；不导出可直接使用的分享令牌、提取码、Webhook 密钥或自动启用规则。导入只恢复内容，不激活分享或外部同步。

Memos 自有格式导入可优先复用；flomo 或其他格式的转换、原生 App、小组件不在本次批准范围。不能因为借鉴 flomo 而推定必须迁移 flomo 私人数据。

### 14.5 私密访问与 AI 边界

私人实例保留必要身份验证，不因单人使用就移除保护。首版提供本人主动创建的限范围分享和主动启用的分区 Webhook；无自动上传第三方分析服务、无默认后台全库 AI 索引。分享页面、媒体和外部同步分别执行自己的授权边界，已有分享链接和 API 权限在后续上线前单独核查。

精确位置和原始媒体只在本人私有档案中默认保留；对外显示副本与私有原件分离。停用、到期或删除对新的访问和未发出的任务生效，但无法保证收回已经下载或被外部平台接受的内容。

使用自己管理的服务器可以符合首版私人使用方案，但不据此宣称端到端加密。若以后要求服务器也无法读取，需另行设计密钥、恢复、搜索和 AI 处理，不能当作 UI 开关。
